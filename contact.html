Privacy & security

How this site works, and how it keeps photos private

A plain explanation of where things live, who can see what, and what protects it.

Two services, two jobs

GitHub shows the page. Supabase keeps everything else.

YouYour browser
page ↑photos ↕
GitHub PagesThe web page
  • Only the site's code: layout, buttons, styles
  • No photos, accounts or messages
  • Public, like any website
SupabaseAccounts, photos & the rules
  • Sign-in and passwords
  • The photos and their details
  • The rules deciding who can see each one
Where photos are stored

In a private storage area, never on GitHub

  • Photos and their small previews are kept in Supabase Storage, in a private area on servers in the US East (N. Virginia) region.
  • Each person's uploads go into their own folder.
  • Nothing is public: a photo can only be opened through a temporary link that expires within an hour, created just for someone who is allowed to see it.
Accounts

Nobody gets in without approval

  • New accounts see nothing until the album owner (or a moderator) approves them.
  • Passwords are handled by Supabase Auth and stored only as one-way bcrypt hashes. Nobody can read them, the admin included.
  • Passwords must be 8+ characters with upper and lower case, a number and a symbol.
Who can see a photo

Members don't see each other's photos unless they're shared

WhoCan see the photo?
The person who added itYes, always. Only they (or an admin) can share, move or delete it.
People it's shared withYes. Shared by name, through a shared album, or with an invite link once they're approved.
All membersOnly if it's shared with everyone.
Other membersNo. It doesn't appear for them at all.
ModeratorsNo. They manage memberships, not photos.
AdminsYes. Admins can see every photo so they can look after the album.
Pending, turned-off or signed-out visitorsNo. Nothing at all.

Anyone who can see a photo can ask for it to be taken down. The request goes to the person who added it and to the admins.

Why it holds up

The rules live in the database, not the page

The web page only asks for photos; Supabase's database decides, row by row, what each signed-in person is allowed to get back. This is called row-level security.

So even if someone copied or changed the page, or talked to the database directly, they would still only get what the rules allow. Uploads, sharing and deleting are checked the same way.

Protection

Encrypted on the way and at rest

  • Every connection uses HTTPS (TLS).
  • Supabase encrypts stored data with AES-256.
  • Who uploaded a photo, and when, is recorded by the server, so it can't be faked.
  • With "Optimize" on, photos are resized in your browser before upload, which also removes GPS location data.
What this site doesn't do

No ads, no tracking

  • No ads, analytics or tracking cookies. Fonts and code are served from this site itself; the only other service your browser talks to is Supabase.
  • The site remembers a few things in your own browser only: your sign-in (if you choose "Keep me signed in"), your light/dark choice, and the Optimize setting.
  • Like any web host, GitHub logs visitors' IP addresses for security purposes.
  • Deleting a photo removes it from storage right away. There's no undo, so the site always asks first.
